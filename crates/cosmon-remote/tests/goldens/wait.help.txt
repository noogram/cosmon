Block until a molecule reaches a status, by polling `GET /v1/molecules/{id}/status` — client-side, so nothing on the server waits for you. Exit 0 when a requested status is reached, 124 on timeout, 125 when it ended some OTHER terminal way (a collapse is not a timeout, and a script must not retry it)

Usage: cosmon-remote wait [OPTIONS] <ID>

Arguments:
  <ID>  Molecule ID to wait on. An exact id, never a prefix: resolving one would cost a full listing to start a loop built to be cheap, and a wait that silently follows the wrong molecule is worse than one that refuses an ambiguous name

Options:
      --for <FOR>                      Statuses to wait for, comma-separated. Defaults to the terminal set, so `wait <id>` means "until it is over" [default: completed,collapsed]
      --profile <PROFILE>              Profile name (default: `default_profile` from config.toml, or `$COSMON_REMOTE_PROFILE`)
      --json                           Render machine-readable JSON instead of human text where applicable
      --timeout <TIMEOUT>              Maximum seconds to wait before giving up. An absolute deadline: it bounds the request in flight, not only the sleep between two of them, so an answer that arrives late is a timeout even when it would have been a success. The contract is your clock [default: 600]
      --poll-interval <POLL_INTERVAL>  Seconds between polls. Clamped to the remaining budget, so a value larger than `--timeout` still terminates on time [default: 5]
      --token <TOKEN>                  Bearer JWT (overrides `$COSMON_REMOTE_TOKEN`). When unset and an authenticated call is made, the CLI uses the OIDC credential recorded by `login`, refreshing it silently; run `login` if none is stored
      --quiet                          Suppress the per-transition progress lines. Implied by `--json`
  -h, --help                           Print help
